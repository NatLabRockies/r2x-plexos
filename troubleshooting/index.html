Troubleshooting

Use the error text or the incorrect result below. The commands use the public-fixture tutorial directory; replace only its paths when diagnosing a study. Preserve original inputs and diagnose a working copy. PluginError adds the lifecycle stage to underlying errors; the stage alone does not identify their cause.

Plugin is missing

Section titled “Plugin is missing”

If the CLI cannot resolve plexos-parser, or Python cannot import r2x_plexos, first identify which interpreter failed. A project installation and the CLI runtime are separate. These checks do not install or modify packages:

The list must include plexos-parser and plexos-exporter. If absent, follow the CLI installation path in that same runtime, then repeat list. If Python scripts fail instead, check:

A version printed by one interpreter does not establish availability in another. Select the environment from environment setup and rerun the exact import that failed.

For Python ABI ... is incompatible with this r2x binary, use the runtime required by that binary; the tested CLI 0.1.15 binary required Python 3.12. Do not change a project’s Python and assume the executable ABI changed. Verify with r2x python show and the CLI runtime guidance.

For option '--show-help' requires a value, use the tested current help command:

Success prints the plugin’s actual configuration flags. Use those flags for the installed release rather than copying legacy Core CLI options.

Could not find PLEXOS XML file or Object = ... not found on the database

These are different failures: the first is input resolution; the second means a named object, commonly the configured Model, is absent in a database that loaded. The tutorial reproduced the second with model_name="NotAModel".

For the pinned fixture, expect Exists: True and Models: ['Base']. If existence is false, correct fpath or restore the input before changing model settings. If Models lists other names, use one of those names for model_name. A filename such as 5_bus_system_variables.xml is not a Model name.

Check the actual pipeline selection:

An xml_file DataStore entry takes precedence over fpath; a directory-valued fpath chooses the first sorted XML. Use an explicit file to avoid selecting a second database. For malformed XML, the failure can be wrapped as Failed to initialize database: ...; the database reader above reproduces that load independently. Restore a valid native XML from the producer rather than editing an Infrasys archive to imitate one.

Verify: preview the corrected path and Model, rerun parsing, then repeat the tutorial component checks. The fixture returns 37 components and five nodes. See parser resolution and missing-Model regression test.

Profile warnings or missing time series despite a successful parse

Section titled “Profile warnings or missing time series despite a successful parse”

Recognizable logs include Failed to attach ..., Failed references (first 5) and Data file not found: .... The parser catches some attachment failures and warns; returning a System does not prove that all requested profiles were attached.

First record the exact component/property and file named in the warning. In the Python workflow, a read-only filesystem check can reproduce path resolution:

Append the actual relative filename from the warning/XML to that base and check Path(...).is_file(). The parser normalizes Windows backslashes to slashes; it does not download missing data. For a missing directory, PLEXOSConfig can instead raise a Pydantic timeseries_dir validation error before parsing begins.

Fix: restore the referenced source CSVs with their original relative layout, or set timeseries_dir to the existing profile directory that really contains them. Keep a DataStore rooted at the run directory rather than relying on a file path as the base. Do not substitute zero profiles merely to silence the warning.

Verify: rerun with Python logging visible:

Repeat component/time-series inspection. Compare series names, timestamps, resolution and values with the source profile. An empty list_time_series(component) query only rules out matching SingleTimeSeries; other types require their explicit query type. The pinned fixture’s first generator has no matching single series, so zero is not a universal error condition.

Evidence: path resolution and attachment, invalid-DataFile regression. This docs update ran the missing-DataFile test; it did not recreate a production study’s unavailable external profiles.

contains no data for the requested year or Horizon start ... is before time series start

Section titled “contains no data for the requested year or Horizon start ... is before time series start”

These messages concern the selected data interval, not plugin discovery. The parser uses the resolved Model horizon’s start year when available, otherwise its configured year. Changing horizon_year alone may not override an XML Model horizon. A property can also depend on scenario, timeslice and component name.

Inspect profile timestamps from the tutorial archive. The process horizon is separate from the saved system:

For the active selection, call get_horizon() in the parsing process before serialization: horizon selection is module-level context, not an archive’s independent study setting. The error Horizon end ... is after time series end is the corresponding upper-bound failure.

Fix: select the intended existing Model/scenario/year and supply profiles that cover its timestamp grid. If a multi-column CSV reports Component '...' not found in parsed file ... Available components ..., compare the reported component key with the source column names as well as the year. Correct the source run/export or its selection, rather than relabelling unrelated data as the requested year.

Verify: rerun the same parse and inspect the required series through its final expected timestamp. The horizon helper and boundary tests establish these messages; both before-start and after-end errors were reproduced during this docs update. A corrected synthetic interval passes. A real study’s calendar recovery requires that study’s actual profile files and was not claimed here.

Archive loading fails

Section titled “Archive loading fails”

Use the portable ZIP produced by --zip -o, not native PLEXOS XML:

The tutorial supplies this script. A module/class import failure means the reading interpreter needs the same model package and compatible Core/Infrasys versions; use the environment checks above and match the writer’s release to source.

If values or units differ after loading, compare a named component in memory and in the archive using the inspection guide. The tested fixture retains Alta’s max_capacity of 40.0 and 34 memberships. A historical nested-quantity serialization issue is recorded in closed issue #53; its closed status is not evidence that every new schema combination works. Preserve both artifacts and report a minimal mismatch instead of editing serialized types or quantity metadata.

If only sys.info() fails with no such table: supplemental_attribute_associations, use the scripted component queries without sys.info() or --interactive and preserve the failing archive. This documented ecosystem summary issue does not establish that components are absent; the workaround does not repair supplemental association metadata.

Report a reproducible failure

Section titled “Report a reproducible failure”

Include these items in a package issue:

  • Exact command or small public-API script, working directory, and failing lifecycle stage.
  • r2x --version, r2x python show, and package versions from the interpreter that failed.
  • Complete error and the log path printed by the CLI; remove confidential data/paths before sharing.
  • Minimal native input plus required companion files, or the complete failing archive and its writer’s versions.
  • Expected versus observed names/counts, timestamp range, resolution and units; target PLEXOS version/template when relevant.
  • Which diagnostic above passed or failed, the one change tried, and the verification result.

During this docs update, failures were reproduced on disposable fixture copies and small synthetic inputs, and 5 focused package regressions passed. Native-file parse/export and archive inspection were verified. Real external profile/calendar data and a licensed PLEXOS solve were not available for recovery testing.
