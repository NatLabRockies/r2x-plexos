# r2x-plexos documentation

Astro/Starlight pages live in `src/content/docs/`.

```bash
npm ci
npm run build
npm run preview
```

Use Node.js 22.12 or newer. Build output is `_build/`, matching the existing Pages publishing directory.
The site base is `/r2x-plexos/`. Search is generated by Starlight/Pagefind during the production build.
Old Sphinx `.html` URLs use static redirect pages in `public/`; section directory redirects are in `astro.config.mjs`.
See [contributor guidance](src/content/docs/contributors.md) for verification.

## API contracts and executable examples

Install the repository's existing Python docs group before building:

```bash
uv sync --group docs
cd docs
npm ci
npm run build
```

The build extracts public top-level exports from the current checkout with
`generate_api.py` and Sphinx, then renders them in Starlight. Source links are
pinned to the checkout revision. Edit docstrings and the generator, not the ignored
`reference/api.md` or `src/generated/api-toc.json` outputs. The native contents
tree exposes members on desktop and mobile.

Write runnable console examples in `python doctest` fences with `>>>`/`...` prompts
and literal expected output or assertions. Each page shares state across its
blocks; every page starts with an isolated copy of the public tutorial fixture.
CLI `read --exec` examples explicitly receive the loaded System as `sys`.
When saving a console example as a script, copy input lines without prompts or
expected output.

```bash
uv run pytest tests/test_docs_examples.py tests/test_docs_api.py --no-cov -q
```

The tests also reject unmarked Python fences, enforce discovery, and check that an
incorrect output expectation fails. Shell/YAML/JSON/signature displays use their
own language fences and are not presented as Python doctests.
